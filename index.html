出来事

論文が示したこと

生物の細胞は、同じ遺伝子を持ちながら分裂（mitosis）と細胞死（apoptosis）を繰り返して体の形をつくり、トカゲの尾のように失った部分を再生します。Fontana のエピジェネティック・トラッキング（ET）はこの過程のモデルです。Mishra らはこれを Kilobot の群れに移しました。全員が同じプログラムと同じ遺伝子を持ち、司令塔なしで、赤外線で近くの仲間とだけ通信しながら、二値画像で与えた形を三角格子の上に組み上げます。形が切られると、残った断片がそれぞれ自分の台数に合わせた縮小版を作り直します。

1. 遺伝子をつくる

正方格子の画像を、上の行ほど半格子ずつ左へずらして斜交座標系（SCS）の三角格子にします。こうすると 6 近傍がすべて等距離になります。画素ごとに Tag=(X,Y)、Flag F（形の内側なら 1）、NN（その場所で持つべき近傍数 0〜6）を並べた表が遺伝子です。NN は画素 (i,j) の (i−1,j)(i−1,j+1)(i,j+1)(i+1,j)(i+1,j−1)(i,j−1) にある 1 の数です。

2. 8 つの状態

  • Queued: 待機列。放送で最小 ID を見つけ、その 1 台だけが列を離れる。
  • Search: 形の周辺をなぞって移動し、入れる格子点を探す。
  • Inactive: 定着したが、隣の Active が Stable になるまで待つ。
  • Active: 近傍数が NN に達するまで新入りを受け入れる。隣に TS の小さい Active がいれば Quasi に退いて一定時間待つ。
  • Stable: 完成した部分。近傍数を監視し続け、減れば Danger。
  • Danger → Leader: 最小 ID の 1 台がリーダーになり、再生を指揮する。

3. Timestep（TS）勾配

定着した順番を表す値です。探索中のロボットは、聞こえる Active のうち TS が最小のものの隣に入ります。古い個体の周りから埋めることで、穴や隙間を防ぎます。

4. 局所化

三角測量の式は使いません。距離 d にいる近傍の座標から、自分が入れる格子点を判断します（論文 図4）。その格子点の Flag が 1 で、隣に Active がいるときだけ定着し、遺伝子から NN を読んで自分の座標を発信し始めます。

5. 再生（Algorithm 2）

  1. リーダー選出: Danger の個体が ID を放送し、より小さい ID を受け取ったら退く。一定時間より小さい ID が届かなかった 1 台がリーダー。
  2. 人口調査: リーダーが断片の外周を一周し、周縁の個体のタグを集める。それをビットマップに写し、閉じた領域の 1 を数えて残りの台数 n を知る。
  3. 縮小画像: 失った台数 K=N−n だけ、現在のビットマップの境界の 1 を順に消す。三角格子が不安定になる消し方は飛ばす。
  4. 共有とシード化: 新しい画像を断片に共有し、リーダーと隣の 2 台が新しいシードになる。座標が新しい形に合う個体は Inactive、それ以外は Queued に戻り、形成をやり直す。

論文の結果: Kilombo シミュレータで T の形成に 2 時間 50 分 8 秒。通信損失確率 0.2 では、遷移を聞き逃した個体が誤った状態に残る（図6）。穴のある形（O など）は苦手。

このシミュレータの作り

すべてのロボットは同じ think() を、毎 tick ランダムな順番で非同期に実行します。判断に使えるのは、自分の記憶と、通信範囲内から確率 1−損失率 で届いたメッセージだけです。メッセージの中身は状態、タグ、TS、形状の版、最小 ID 推定などです。描画と統計はシミュレータ側の神の視点ですが、ロボットの判断には使っていません。

論文どおりに実装したところ

  • 二値画像 → SCS → 遺伝子 (Tag, F, NN) の計算。原点は画像中央の 1。
  • 8 状態の遷移、TS の継承（隣の Active の TS+1）、Quasi への退避と復帰。
  • 待機列からの出発（最小 ID を放送で決め、一定時間後に次へ）。
  • 損傷検出（Stable の近傍数が NN 未満）、最小 ID によるリーダー選出、外周の一周による人口調査、境界を削る縮小、新シードからの再形成。
論文に書かれていない部分の補い方（補助ルール）
  • 近傍の相対位置（距離と方位）が測れるものとしました。実機の Kilobot は距離しか測れません。
  • 入る格子点を決めたら、近傍の座標から推定した格子上の短い経路（最大 5 歩）を通って入ります。
  • 各ロボットは、自分の 6 近傍のどこが埋まっているかを 6 ビットで発信します。探索中の個体は、これで少し広い占有地図を持ちます。
  • 穴を作らない: 空いたセルが外とつながらなくなる位置には入りません。周りが 4 方向以上埋まったくぼみは、TS 最小の規則の例外として先に埋めます。移動中の仲間も閉じ込めません。
  • Inactive が遷移の瞬間を聞き逃しても、同じ形の Stable の隣で 60 tick 待ち、隣に Active がいなければ Active になります。
  • 待機列は「外側の個体」から出発します。最小 ID の規則はその中で守ります。こうしないと、細い腕の先の個体が取り残されて迷子になります。
  • 縮小形状は、残った個体と最も重なる位置と向き（60° 刻み）に置きます。論文の「座標が新しい形に合う個体は Inactive」を素直に読んだ実装です。
  • 縮小版を作れない（シードにできる三角形がない）ときは、残った形をそのまま新しい形とします。
  • リーダー選出と新しい形状の受け取りは、接している個体どうしで中継します。切断で分かれたかたまりごとに再生するためです。
  • 迷子になった探索個体は、最後に聞こえた仲間の方へ戻ります。長く仲間が聞こえなければ、近くの別の群れに加わります。
  • 切断では、線の片側を通信範囲の外まで引き離します。論文と同じく、線上の個体は失いません。

「補助ルール」のチェックを外すと、穴防止、くぼみ優先、外側からの出発、遷移の聞き逃しの救済が止まります。論文の規則だけで動かしたときの違いを観察できます。

観察のポイント
  • 最初の 3 台（シード）から形が育ちます。TS の小さい Active（赤）の周りから埋まり、Quasi（黄土色）が順番待ちをします。
  • 損失率を 0 にすると速く、0.4 以上にすると遅くなります。誰も中央から指示していないのに、形は崩れません。
  • 完成後に「横に切る」を押すと、両方の断片で Danger（黄）が出ます。それぞれリーダー（桃色）を選び、外周を一周してから縮小版を作り直します。新しい形は 60° 単位で向きが変わることがあります（論文 図7 と同じ）。
  • ロボットを選ぶと、そのロボットの記憶にある近傍の表が見えます。群れ全体の地図は、誰も持っていません。
