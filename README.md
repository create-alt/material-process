# 研究室リサーチHub（情報系）

情報系（情報科学・情報工学・コンピュータサイエンス）の **大学・大学院・研究室** を調べるためのWebアプリです。
研究室紹介ページ・研究室一覧・大学院入試要項・編入学募集要項などのテキストをコピペ（またはURL指定）するだけで、

- **大学名** と学部・研究科・学科・専攻
- **研究室ごとの特徴**（教員・研究分野・研究内容・雰囲気・実績・進路・研究室訪問）
- **入学・編入の条件と方式**（編入学 / 大学院入試 / 学部入試 ごとの出願資格・試験科目・英語試験・日程・募集人員）

を自動で整理し、気になる研究室を **チェック → 保存 → 比較 → 詳細表示** できます。

大学のトップページなどのURLを1つ入れるだけで、**リンクを自動でたどって研究室一覧・教員一覧・入試ページを探し、分野別の研究室リストを作る「サイト自動探索」** と、
PC上で動く **ローカルSLM（小規模言語モデル）** による文脈判定にも対応しています。

---

## 🌟 主な機能

0. **🕸️ サイト自動探索（クローラー）＋ 🧠 ローカルSLM**
   - 大学・研究科のトップページから、`<a>` タグを「研究室一覧」「教員紹介」「研究科・専攻」「入試・編入」に近い順にスコアリングしてたどります（同じドメイン内のみ・robots.txt遵守・1ページごとに待機）。
   - 医学部・文学部など他分野へのリンクやニュース・アクセス等は後回しにし、情報系を優先して探索します。
   - 各ページを「見出し・リスト・表・カード」の行構造に変換し、**「〇〇研究室」と書かれていない教員名の列挙**（例:「山田 太郎 教授　自然言語処理」、表の「教員｜職名｜研究テーマ」、`<h3>氏名</h3><p>准教授</p>` のカード）からも研究室を抽出します。
   - ページの「〇〇分野」「〇〇講座」などの見出しで **分野別に分類**（研究分野タグでの分類にも切替可）。各研究室ページもたどって概要・キーワードを補完します。
   - ローカルSLMを有効にすると、番号付きの行をモデルに読ませて **文章中の研究室（「加藤先生の研究室では…」など）も文脈から判定** し、入口ページでは「どのリンクをたどるべきか」もモデルが判断します。
   - SLMの出力は行番号で根拠を照合し、**ページに書かれていない研究室名・分野は採用しません**（捏造対策）。
   - 見つかった研究室にチェックを付けて「解析結果に読み込む」と、入試ページの情報と合わせてフォームに反映されます。
   - 貼り付けテキストの解析でも同じ抽出エンジン（＋SLM）を使い、教員名だけの一覧から研究室を拾います。

1. **大学 → 研究室 の階層で自動整理**
   - 「■山田研究室（教授 山田 太郎）」「知能情報学講座 佐藤研究室」「Yamada Lab」「| 教員 | 教授 … |」（Markdown表）など、表記の揺らぎを吸収して研究室を分割します。
   - 見出しのない自由文（メモ・ブログ）でも「〇〇研究室」の言及から研究室を拾い、続く文を説明としてまとめます。
   - 同じ大学を再度保存すると、既存の大学に研究室・入試情報を **統合** します（重複しません）。

2. **研究室の「特徴」を自動抽出**
   - 情報系18分野の辞書（AI・機械学習 / 自然言語処理 / CV / HCI / セキュリティ / ネットワーク / HPC / ソフトウェア工学 / 量子 …）で **研究分野タグ** を自動判定。
   - 本文から「コアタイムなし／あり（時間）」「週1回のゼミ」「国際会議での発表実績」「企業との共同研究」「GPU等の計算資源」「外部生・編入生の受け入れ」「RA等の経済支援」「メンバー数」「進路」などを箇条書きの特徴として表示します。

3. **入学・編入の条件と方式**
   - 編入学（高専・短大からの3年次編入など）・大学院入試（博士前期/後期、一般選抜・推薦・社会人など）・学部入試をタブで管理。
   - 出願資格 / 試験科目・選抜方法 / 英語・外部試験（TOEIC・TOEFL）/ 日程 / 募集人員・倍率 / 備考（過去問・事前相談）に振り分けます。
   - 見出しがなくても「編入」「院試」「TOEIC」を含む文を拾って記載します。

4. **気になる研究室のチェック・保存・比較・詳細表示**
   - ★で気になる研究室をチェック、志望度（5段階）とステータス（調査中・訪問予定・訪問済・第一志望・出願済 など）を管理。
   - 最大6研究室を横並びで **比較表** 表示（共通の研究分野をハイライト、「違いがある項目だけ表示」、比較表のCSV保存）。
   - 研究室の **詳細モーダル** で全項目・その大学の入試情報・メモ（自動保存）を確認できます。

5. **おすすめ機能**
   - 🎯 **興味分野マッチ度**: 興味のある分野・キーワードを登録すると、研究室ごとのマッチ度（%）を算出し、マッチ度順に並べ替え。
   - 📅 **重要日程タイムライン**: 出願期間・試験日・合格発表・説明会・研究室公開の日付を抽出し、全大学分を「あと○日」付きで時系列表示。
   - 🤝 **研究室訪問チェックリスト**: コアタイム・ゼミ頻度・院試対策・外部生の受け入れ・進路など、訪問時に確認したい12項目をチェック管理。
   - 💡 **未取得項目の表示**: 進路や研究室訪問など、まだ情報がない項目を「訪問で確認すべきこと」として提示。
   - 🔍 **絞り込み**: キーワード検索・研究分野・ステータス・★のみ・並び替え（マッチ度 / 志望度 / 名前）。
   - 💾 **CSV / JSON**: Excel対応CSV（UTF-8 BOM付き、1研究室 = 1行、列カスタマイズ・★のみ出力可）と、JSONでのバックアップ／復元。

6. **テキスト選択マッピング**
   - 貼り付けたテキストの一部を選択し、「大学名へ」「試験科目へ」「＋研究室として追加」などのボタンで手動で割り当てられます。

7. **AI解析（Google Gemini API）オプション**
   - APIキーを設定すると、崩れた文章や英語ページもLLMで構造化し、内蔵パーサーの結果で空欄を補完します。

すべての処理はブラウザ内で完結し、データはブラウザの `LocalStorage` に保存されます。

## 🚀 起動方法

### 方法1: ブラウザで直接開く
`index.html` をダブルクリックしてChrome / Edgeなどで開きます（URL取得は公開プロキシ経由になります）。

### 方法2: ローカルサーバーで起動（推奨：サイト自動探索・ローカルSLMが安定）
```bash
python server.py 8000
```
ブラウザで `http://localhost:8000` にアクセスしてください。`/api/fetch-url` でページ取得を、`/api/slm` でローカルLLMサーバーへの通信を中継します（中継先は localhost のみ）。

## 🧠 ローカルSLMの設定（任意）

ヘッダーの「🧠 ローカルSLM」から選びます。使わない場合もルールのみで動作します。

| 方式 | 特徴 | 準備 |
| --- | --- | --- |
| ブラウザ内で実行 | インストール不要。**GPU（WebGPU）が使えればGPU、使えなければCPU（WebAssembly）で自動的に実行**します。初回のみモデルをダウンロードしブラウザにキャッシュ | 不要 |
| ローカルLLMサーバー | Ollama / LM Studio / llama.cpp など。GPUがなくてもCPUで動作し、大きめのモデルも使える | 例: [Ollama](https://ollama.com) をインストールし `ollama pull qwen2.5:3b` |

ブラウザ内実行のエンジンは「自動 / GPU優先 / 常にCPU」から選べます。

| エンジン | ライブラリ | 推奨モデル | 備考 |
| --- | --- | --- | --- |
| GPU | WebLLM（WebGPU） | Qwen3.5 2B ／ 軽量: Qwen3.5 0.8B ／ 日本語特化: Gemma 2 2B JPN | 高速。WebGPU対応の最新Chrome/Edgeが必要 |
| CPU | Transformers.js（ONNX Runtime Web / WebAssembly） | Qwen3 0.6B ／ 最軽量: Qwen2.5 0.5B ／ 日本語◎: Gemma 3 1B | GPU不要。Web Workerで動かすため画面は固まりません |

- GPUが検出されても初期化に失敗した場合（ドライバ・VRAM不足など）は、自動でCPU実行に切り替わります。
- CPU実行は `python server.py` で開くと **複数スレッド** で動作し高速になります（cross-origin isolation用のCOOP/COEPヘッダーを付与しているため）。`index.html` を直接開いた場合は1スレッドです。
- CPU実行はGPUより遅いため、1回に読ませる量を小さくし、サイト自動探索では1ページあたりの判定回数を最大4回に絞ります（ルールによる抽出は全体に適用されます）。また出力形式を制約できないため、回答の書き出し（JSONの先頭）を固定し、途中で切れた出力も完結した要素までを復元して使います。

「モデルを準備してテスト」で動作確認できます（実際に使われるのがGPUかCPUかも表示されます）。SLMの判定には1ページあたり数秒〜数十秒（CPUではさらに長く）かかるため、最大ページ数は20〜30程度から始めるのがおすすめです。

## 📖 使い方

1. **読み込み**: 次のいずれかの方法で読み込みます。
   - 「🕸️ サイトを自動探索」: 大学・研究科のトップページのURLから研究室一覧を自動収集し、チェックした研究室を読み込み
   - 研究室一覧・研究室紹介・入試要項ページのURLを入力して「URLから取得＆解析」
   - テキストを貼り付けて「研究室・入試情報を自動解析」
   - 画面上部のサンプル（架空の大学）で動作を試せます。
2. **確認・編集**: 右側で大学情報・入試タブ（編入学/大学院入試/学部入試）・研究室カードを確認・修正し、「大学・研究室を保存」。
3. **整理・比較**: 下部のリストで★チェック、志望度・ステータスを設定。「比較」にチェックするか「★の研究室をまとめて比較」で比較表を開きます。
4. **詳細・メモ**: 研究室名をクリックすると詳細表示。訪問チェックリストとメモを記録できます。
5. **出力**: 「CSVエクスポート」または「JSONバックアップ」。

> ⚠️ 自動抽出の結果は必ず大学の公式な募集要項で確認してください。入試日程の年が書かれていない場合は「年推定」と表示されます。

## 📂 ファイル構成

- `index.html` : メイン画面
- `css/style.css` : スタイルシート
- `js/parser.js` : 大学・研究室・入試情報の揺らぎ吸収パーサー（日程抽出を含む）
- `js/lab-extractor.js` : ページの行構造化・研究室候補のスコアリング・SLMによる文脈判定と検証・リンク評価
- `js/crawler.js` : サイト自動探索（優先度付き探索・robots.txt・研究室ページ補完・入試情報の統合）
- `js/slm.js` : ローカルSLM連携（ブラウザ内GPU: WebLLM / ブラウザ内CPU: Transformers.js / Ollama / OpenAI互換サーバー）
- `js/slm-worker.js` : ブラウザ内CPU実行エンジン（Transformers.js + WebAssembly）。`index.html` を直接開いた場合（file://）でも動くよう Blob URL のWeb Workerとして起動し、Workerが使えない環境では画面側で実行
- `js/insights.js` : 研究分野辞書・特徴抽出・興味マッチ度・訪問チェックリスト
- `js/url-fetcher.js` : URL取得とHTML/Markdownの構造化テキスト変換
- `js/ai-parser.js` : Gemini API連携モジュール（オプション）
- `js/samples.js` : 動作確認用のサンプル（架空の大学・研究室）
- `js/app.js` : 画面制御、保存・統合、比較、詳細表示、日程、CSV/JSON入出力
- `server.py` : ローカルサーバー（URL取得プロキシ・ローカルLLM中継）
